# Does Aurora's last WFI (timers masked, IPI and AIC events acked, WFI retaken) let sequence 0 start? (milestone 4, item 2)

```
Question      If every core masks its two arch timers and clears IPI_SR after each WFI return, and
              core 0 also acks the AIC's next event (Aurora sleep.c 1622-1640, 3418-3430;
              irq-apple-aic.c 486-489, 1f38ff8f4), does the always-on engine start sequence 0?
Known         Our cores wait after their final write in "dsb; isb; wfi" loops with DAIF masked,
              timers and IPI_SR untouched, no AIC read (probe tree glue.c 417-455). A pending
              timer, IPI or AIC line ends a WFI even with DAIF masked. ds29 and m3 run 5 had
              wakemark=3 and no 'DA' record: core 0's wait did not record a WFI return after
              alarm + 2 s (or the write did not land) [evidence 2026-11-17 README 4826-4828].
              Whether a timer, IPI or AIC event is pending on core 0 at its last write: not read.
Prior art     Aurora linux-integration 1f38ff8f4 as above; tools/prior-art.sh wake, aic: nothing
              of ours on the last WFI.
Outcomes      A  0x0201 04 -> 01, or a reset 5-7 s after the commit -> one of the batch's switches
                 lets sequence 0 start: halve (m4fix bits 0-1 against the rest).
              B  04 -> 04, back at ~165 s -> with the rest of the batch, ruled out together.
              C  no record, no commit, or another time -> inconclusive; read real.out/dmesg.
              Side reading, k 173 bits 16-20 (or k 176): F, I, timer, IPI pending on core 0 at
              its last write; 0 = nothing was there for this step to clear.
Tell apart    0x0201 read after the run (nvmem), the reset time against the start, the record.
Not covered   Cores 1-7's pending state (only core 0 is read); events after core 0's last write.
Safety        Probe kernel probe/m4-batch (boot once, m1-bootonce), safety-checked by a second
              agent before run 1; claim taken; watchdog 1 held at 120 s through /dev/watchdog0 from
              before any trigger (m3run.sh idle mode), apple_wdt unbound by start.sh, wdt=150
              armed in begin and at the commit point; the M1 comes back on stock by the watchdog.
              Nothing needs Naeem.
Budget        Shares milestone 4's build (2 at most) and run 1 (4 runs at most); 1 agent writes the
              probe, 1 checks it.
Result        (after the run)
```
