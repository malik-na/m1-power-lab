# Does the P cluster reach off 50 ms after cores 4-7 go down? (milestone 2, run 8)

```
Question      Read 50 ms after cores 1-7's final writes (core 0 held by the sampler), is
              0x23b718004 (P cluster) 0x00 (off) or still 0x10 (state 1)?
Known         0x23b718004 = 0x10 read microseconds after cores 1-7's final-write jobs return, with
              and without an L1 clean [runs 4, 5; 2026-11-20-m2-core-cache-clean.md]. Bits 4-7 are
              a state: macOS's wake reads 0 there after a power-down and polls 0x1f -> 0x2f when
              bringing the cluster up [spec 3457-3462, 3749]. Core 0 held 50 ms gives no
              watchdog-2 reset [2026-11-20-m2-engine-window.md].
Prior art     none.
Outcomes      A  0x00 -> the P cluster powers down under Linux; the cluster is not what the engine
                 waits on (it is down, core 0 still up).
              B  0x10 -> the P cluster stays in state 1 for 50 ms with its four cores in WFI: it is
                 held from finishing power-down; a candidate for what the engine waits on.
              C  other value -> read it against the 0x1f/0x2f/0 pattern.
Tell apart    k 157 (read by core 0 after the 50 ms sampler, before its own final write).
Not covered   The E cluster (core 0 is in it and still up); why, if B.
Safety        Kernel m2cache e1442a487 (safety-checked), m1fix=4 (sampler, reads only), m1aop=0,
              wdt=150, boot-once.
Budget        0 builds, 1 run (the milestone's last).
Result        C. Run 8, 2026-11-20 04:28:23 (m2cache e1442a487, m1fix=4, m1samp_ms=50, m1aop=0,
              probe_k=157): record 44 71 9d 80 50 00 00 00 9d 00 = 0x23b718004 = 0x00000050 after
              the 50 ms sampler; stock kernel 04:31:09 = 166 s; 0x0201 04 -> 04. The P cluster word
              moves (0x10 at once, 0x50 at 50 ms) but is not 0. What 0x50 means (bit 6) is not
              known; macOS's value with its cores down is not read. Next: that macOS reading
              (2026-11-20-m2-hv-p-cluster.md). Raw: var/milestone2/run8-start.txt, run8-after.txt.
```
